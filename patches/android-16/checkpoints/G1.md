## 目标

把 M1 boot 的 `device/generic/*` overlay **并入统一板** `device/bst/qvirt`，新增 win 产品 `bst_x86_64`，与 mac `bst_arm64` 同板、arch 差异下沉 BoardConfig。generic 路径**暂不下线**（安全网）。

## 策略（安全网 step 1）

**不物理搬迁** generic 文件树——`bst_x86_64.mk` 继承 `device/generic/common/x86_64.mk`（已验证的 M1 boot 内容），仅 override 产品身份（`PRODUCT_DEVICE=qvirt` 等）。验证等价后再考虑把 overlay 文件迁入 qvirt 目录。

## Layer2（当前）

| Oracle | 结果 |
|---|---|
| system_mounted / init_second / odsign | PASS |
| boot_completed / launcher / ready / hide_boot | FAIL |

**★ 根因（2026-07-16 定位，readback 验证）= `vndservicemanager` 缺失**（非图形）。完整 guest 日志：`init: start vndservicemanager ... failed: service not found` + 多个 vendor HAL（allocator/light/power/composer）`Could not register service (-2147483648)`。vndservicemanager 在 Android.bp 是 `vendor:true` → `m systemimage` 不构建；M1 用 `m droid`（含 vendor 镜像）才有，G1 改 `m systemimage` 后断了。详见 [G1-layer2-failure.md](G1-layer2-failure.md) 「真正根因」节。

**修复（进行中）**：`m vndservicemanager` 单编（产物 md5 `8ebc3723…`）→ overlay 进 staged `system/vendor/{bin/vndservicemanager,bin/vndservice,etc/init/vndservicemanager.rc,etc/selinux/vndservice_contexts}`（已写入 `g1_apply_boot_overlays.sh`，标 temp_debt，G9 收口对齐 M1 build_make 对 hwservicemanager 的处理）→ r228 重打 → Layer2 重验。

- **禁止**从 backup Root.vhd 抽取图形库；必须 `mmm` + stage readback。
- 禁用 `keymint-service.rc` 会卡 odsign / `android.security.maintenance` — G8 不得移出 keymint。
