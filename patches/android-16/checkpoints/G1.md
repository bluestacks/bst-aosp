## ★ Shell Transitions 临时 patch（r262）— temp_debt

**症状**（引自 boot-guide § Settings Activity）：`service check auth` found；Settings `RESUMED` + uiautomator 树完整，但黑屏；WM 判大量窗口 `EXITING` / `mAnimatingExit`；SF 层 `hidden by parent`；`SurfaceSyncGroup: Failed to receive transaction ready`；`BLASTSyncEngine: never received commit callback`。

**根因**：A16 Shell Transitions 默认开；`Transition Root` leash 的 **BLAST/SF transaction commit callback 在 goldfish 路径不返回** → 窗口卡在过渡态。runtime 属性无效（`ENABLE_SHELL_TRANSITIONS` 编译期常量）。

**TEMP patch**（`patches/android-16/patches/aosp16__frameworks_base__r262-temp-disable-shell-transitions.patch`；base `45034f0663…`）：
1. `ENABLE_SHELL_TRANSITIONS = false`
2. `onInit()` 用 `if (ENABLE_SHELL_TRANSITIONS)` 包住 `registerTransitionPlayer` / `unifyShellBinders`

**验证**：`Transition Root` = 0；Settings SF layer visible + Output Layer。r262 TEMP patch 在当前 G1 基线镜像 Root.vhd `2a7a497a`（cont.4）内。（注：早期 `6046387b` 是从未真部署的 r262 时期镜像，见顶部 badge 订正。）

**影响**：Settings **界面可见**（否则黑屏），但 shell transitions 全局关闭（影响动画/多任务 UI 行为）。修复前，G1 的 Settings 可用性测试取决于本 TEMP。

**temp_debt → Phase 2 P2-TEMP-BLAST**：修复 goldfish/SF BLAST commit callback 后删本 patch，恢复 `ENABLE_SHELL_TRANSITIONS=true`。

**已知缺失项**（在 OUT 目录之后仍缺失，由构建脚本的打包步骤提供；非覆盖层）：
- `hwservicemanager` + rc — 本应由 `build_make` 补丁（`system_image_defaults`）安装在 `/system/bin/` 下，但在 `qvirt/` 的输出目录中缺失
- Composer/allocator VINTF manifest — 本应由 HALs 的 `vintf_fragment` 提供；在 `qvirt/` 的输出目录中缺失
- `system_ext` HIDL allocator — `system_ext` 分区内容；该产品无法构建 system_ext
- Launcher + BST tools — 来自构建脚本的 `apks` 目标和 BSTTOOLS 副本，非 AOSP 构建

**解决方案**：这些属于构建脚本的打包流程（`copy_android_files_to_outputdir` + BST 工具副本 + APK 副本）和构建配置的整合（使 `system_ext`/VINTF 片段能够在 `bst_x86_64` 产品上运行）。属于 G9 构建适配任务，并非本阶段解决的临时覆盖层。

**当前 Root.vhd**：通过清理后的流水线 `g1_build_libs → 暂存 → r228` 生成（等待测试）。

## 踩坑速查（gotchas，后续调试必读）

本工作单元踩过的坑（详细根因见 porting-log cont.1~cont.4）：

1. **UUID 看错对象**：`VBoxManage showhdinfo` 显示的是**注册表缓存值**（54e9ad31），不是 VHD 文件 footer 实际值。验 UUID 要 hexdump VHD **footer offset 64**（16 字节 mixed-endian）。r228 远程 `sethduuid` 曾报「UUID changed」但没真改 footer（BstkVBox 怪行为）。
2. **Data.vhdx 勿删**：干净首启用 `Data_orig.vhdx → Data.vhdx`（copy），**不能删 Data.vhdx**。VBox 需文件存在，否则 `Could not open medium Data.vhdx` → GlueStartVM fail → 卡 [Initializing]（曾误判为 UUID）。
3. **create_vdi「挂起」实为 chown read-only abort**：r228 复用旧 Root.fs（内含旧 dataFS）挂载态 read-only → chown 失败 → set -e abort（在 create_vdi 之前）。解：r228 开头清 nbd + 重建干净 Root.fs。
4. **launcher 在 Priv-Downloads 段（非 SystemPrivApp）**：buildscripts `copy_system_apks` 遇 Data: 就 break，不拷 launcher → G1 删 dataFS 后 launcher 缺 → FallbackHome。故 `g1_copy_bst_apks.sh` 用 **硬编码 APK 列表 force 预装 priv-app**（不读 APPCONFFILE）。历史教训：早期版本读 APPCONFFILE 须 `tr -d '\r'`（CRLF），否则 `case "System:"` 匹配不上 → copied=0；现版改硬编码绕开。
5. **pkill -f 自杀**：`pkill -f r228-pack-root.sh` 在「含该字符串的命令」里会匹配到当前 shell 自杀 → 后续命令不执行。按 PID 杀或分开命令。
6. **present-fence 日志非致命**：`SurfaceFlinger: trackPendingFrame: Invalid present fence`（58677×）是 goldfish hwcomposer 返回 -1 retire fence（M1 同 EmuHWC2 同样如此，M1 也 boot 可见）。**勿当阻塞追**。cont.3 曾误判。
7. **stale-oracle 字符串**：`g1_boot_verify.ps1` 旧 `Player state: ready` 永不命中（HD-Player 用 `[Ready]` tag）→ 成功 boot 也判 FAIL（假阴性）。教训：oracle 字符串要先验真格式。
